Đi theo thứ tự gợi ý hoặc chọn ngay phần bạn cần. Tiến độ chỉ lưu trên trình duyệt này, không tự đồng bộ giữa các thiết bị.

Sau chương này, bạn làm được gì?

  • Mô tả được vai trò client, server và một lượt HTTP request–response.
  • Mở dự án bằng VS Code, chạy qua HTTP cục bộ và quan sát bằng DevTools.
  • Lưu một phiên bản bài làm bằng Git, không đưa mật khẩu hoặc khóa API vào repository.

Kiến thức cần nắm

Client, server và HTTP

Trình duyệt là client: gửi request tới server, nhận response rồi xử lý HTML, CSS và JavaScript. Response có mã trạng thái, header và có thể có body. 200 thường biểu thị thành công; 404 nghĩa là không tìm thấy tài nguyên; 204 không có body.

Đọc lỗi bằng DevTools

Network cho biết URL, method, status, header, response và thời gian tải của từng request. Elements dùng xem DOM/CSS; Console xem thông báo và lỗi JavaScript. Mở Network trước khi tải lại trang để ghi nhận các request.

Quy trình làm việc

Tạo thư mục dự án → sửa tệp → chạy server cục bộ → kiểm tra trình duyệt → git diff → git add → git commit. Git lưu lịch sử phiên bản; GitHub là dịch vụ lưu trữ và cộng tác, không phải chính Git.

Thực hành có hướng dẫn

Thời gian thực hành gợi ý: 45 phút, có thể chia thành nhiều lượt.

Tạo trang giới thiệu bản thân và ghi lại một lượt tải trang.

  1. Tạo index.html có tiêu đề và một đoạn giới thiệu; mở thư mục bằng VS Code và chạy bằng Live Server theo bài hướng dẫn môi trường.
  2. Mở DevTools → Network, tải lại trang, chọn request tài liệu HTML; ghi URL, method, status và Content-Type. So sánh với một request ảnh nếu có.
  3. Đổi nội dung, tải lại để xác nhận; xem git diff rồi commit các tệp bài làm. Viết 3–5 dòng giải thích browser và server đã làm gì.

Tự kiểm tra bài làm trước khi chuyển chương

  • Địa chỉ trang bắt đầu bằng http:// hoặc https://, không phải file://.
  • Chỉ ra được request tài liệu HTML và phân biệt nó với request ảnh/CSS.
  • Có tệp bài làm, bản ghi Network và một commit; không chứa thông tin bí mật.

05 · Promise · async/await

Promise: đang chờ, thành công, hoặc thất bại

⏳ pending

Đang chờ kết quả.

✅ fulfilled

Hoàn tất, có kết quả.

⚠️ rejected

Thất bại, cần xử lý.

async function loadEvents() {
  try {
    const response = await fetch('/events.json');
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const events = await response.json();
    render(events);
  } catch (error) {
    showError('Không tải được sự kiện');
  } finally { hideLoading(); }
}
🎙 Lời dẫn: async/await khiến mã dễ đọc như tuần tự, nhưng chờ mạng không khóa trình duyệt. Fetch trả Promise; await đợi kết quả; try/catch xử lý lỗi. Cạm bẫy: HTTP 404 không tự làm fetch reject. Vì vậy phải tự kiểm tra response.ok rồi mới đọc dữ liệu.

10 · Fetch: request thật

Gửi request, kiểm tra response, rồi mới render

async function loadAppointments() {
  setState('loading');
  try {
    const response = await fetch('/api/appointments');
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();
    if (!Array.isArray(data)) throw new Error('Sai schema');
    setState('success', data);
  } catch (error) { setState('error', error); }
}

Demo cần nói thật

🎙 Lời dẫn: Đây là vòng đời của một request thật. Trước khi gọi fetch, chuyển sang loading. Khi nhận response, kiểm tra response.ok vì fetch không tự coi 404 hay 500 là lỗi JavaScript. Sau đó đọc JSON và kiểm tra dữ liệu có đúng mảng mà giao diện cần hay không. Chỉ khi ba cửa đều qua, ta mới render success. Nếu có lỗi, chuyển sang error và giữ một lối thử lại.

11 · Lỗi, CORS, timeout & race

Lỗi mạng không chỉ có một loại

CORS

Trình duyệt chặn khác origin nếu server chưa cho phép.

Timeout

Request chờ quá lâu; cần AbortController hoặc giới hạn thời gian.

Race condition

Kết quả cũ về sau có thể ghi đè kết quả mới.

Biện pháp

Hủy request cũ, gắn requestId, hoặc nhận kết quả mới nhất.

Mở Console và Network để tìm bằng chứng.

🎙 Lời dẫn: CORS thường không phải lỗi frontend có thể sửa bằng một tùy chọn tùy tiện; server phải cấu hình quyền truy cập đúng. Timeout là lúc hệ thống không phản hồi đủ nhanh, nên giao diện cần dừng chờ và cho thử lại. Race condition xuất hiện khi gõ liên tục hoặc đổi bộ lọc nhanh: request cũ có thể về sau request mới rồi ghi đè dữ liệu. Có thể hủy request cũ bằng AbortController hoặc kiểm tra requestId trước khi cập nhật state.

Lưu ý dựng video: Phân biệt CORS, HTTP và lỗi mạng; không gom tất cả thành “fetch lỗi”. Khi minh họa race, cho request A và B chạy song song, rồi nhấn mạnh thứ tự hoàn thành có thể ngược thứ tự gửi. Câu chuyển: hiểu rủi ro kỹ thuật rồi, ta chuyển sang phân tích sản phẩm.

Race condition xử lý thế nào?

Gợi ý: Hủy request cũ hoặc nhận kết quả mới nhất.

🎙 Lời dẫn: Hãy tạm dừng và trả lời bằng lời của mình. Kiểm tra response.ok giúp ta phân biệt phản hồi HTTP không thành công với lỗi mạng. Mảng rỗng sau status 200 là empty state, không phải error. Khi đổi bộ lọc, kết quả mới thường bắt đầu từ trang một để người dùng không bị đặt ở một trang không còn dữ liệu. Với race condition, ta cần bảo đảm kết quả cũ không ghi đè kết quả mới, bằng cách hủy request hoặc kiểm tra mã request trước khi cập nhật state. Câu trả lời tốt phải có cả lý do và hệ quả đối với người dùng.

Dữ liệu

State gốc có một nơi; danh sách lọc được dẫn xuất chưa?

  1. Nhập từ khóa có khoảng trắng và không có kết quả.
  2. Đổi bộ lọc ở trang cuối rồi kiểm tra trang hiện tại.
  3. Chọn một card và xác nhận các vùng liên quan cùng cập nhật.
  4. Refresh để phân biệt state tạm với dữ liệu cần lưu.
🎙 Lời dẫn: Đây là bảng tự kiểm ngắn cho hai năng lực quan trọng. Với tìm kiếm, hãy thử không chỉ trường hợp gõ đúng mà cả khoảng trắng, chữ hoa và kết quả rỗng. Với component, hãy chọn một sự kiện rồi xem card, form và phần tóm tắt có cùng phản ánh một lựa chọn hay không. Nếu mỗi vùng có một bản sao state riêng, lỗi đồng bộ sẽ xuất hiện. Cuối cùng, refresh trang để hỏi dữ liệu này là state tạm thời hay phải đọc lại từ storage hoặc server.
